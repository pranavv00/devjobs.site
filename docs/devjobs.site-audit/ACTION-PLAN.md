# Deployment and measurement plan

The local implementation is ready for the remaining environment-dependent checks. The production site has not been changed.

1. Run `npm ci`, `npm run check`, `npm run build`, `npm run verify:build`, and `npm run test:browser` in CI or a machine that permits Chromium and localhost. The local production build and static checks passed; browser execution was blocked, so it remains required before treating the release as visually and interactively verified.
2. Review the homepage and search/detail routes at 320, 390, 768, and 1440 pixels. Confirm search is visible in the first screen, filters and browser history restore values, pagination retains filters, saved jobs still work, and application links are reachable near the detail title. Exercise the no-JavaScript GET fallback.
3. Publish the tested Next.js root project through the existing Vercel project. This checkout has no Git metadata or configured Vercel project access; do not deploy the optional Astro frontend over the existing Next.js deployment.
4. Verify canonical and legacy job URLs on production, one genuinely missing job (404), filtered-results noindex, sitemap/RSS, security headers, and a supported JobPosting page using Google’s Rich Results Test. Verify old `/?q=React` links redirect to `/jobs?q=React`.
5. If the Vercel plan supports custom events, set `NEXT_PUBLIC_ENABLE_ENGAGEMENT_ANALYTICS=true` and rebuild. Confirm `search_jobs`, `filter_jobs`, `view_job`, `save_job`, `unsave_job`, and `apply_click` appear only after the corresponding user action. Events must not contain search text, saved skills, application data, or destination URLs. Default is disabled; standard page-view analytics remain configured.
6. Compare seven-day production windows against the supplied baseline: 504 visitors, 652 page views, 86% bounce. Segment by landing page, referrer, device, and country. Separately inspect the October 28 traffic spike. Success is improved relevant-job discovery and application intent, not an artificial bounce reduction. If mobile search-to-detail and application-click rates do not improve, revisit landing-page relevance and acquisition traffic before adding more UI.
7. Measure field LCP/INP/CLS with Vercel Speed Insights or Search Console, and run mobile Lighthouse as lab evidence. Current goals are good CWV thresholds; no before/after score is asserted. Keep initial discovery summaries under 25 KB and homepage HTML under 300 KB; tests enforce these budgets.
8. Verify that twice-daily scraper updates trigger successful deployments, then check freshness and expired-job removal. Complete the Claude SEO installation using its upstream instructions outside this restricted workspace; rerun its full crawl once the runtime and network are available.

Remaining deliberate tradeoffs: browser-local skill matching downloads the summary catalogue on `/matches`; location is text-based evidence rather than a country-eligibility engine; saves remain on one browser; no field performance, indexing, ranking, or bounce improvement is guaranteed by this code change.
