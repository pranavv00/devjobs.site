# SEO implementation findings

Audit date: 2026-11-01. Scope: local Next.js routes and shared discovery components. These findings do not establish live index coverage, rich-result eligibility, or field Core Web Vitals.

| Priority | Evidence                                                                                                                                                                  | Change                                                                                                                                                                  | Verification                                                                                                                                                                     |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| High     | `jobs/[slug]` had `dynamicParams = false` while only canonical slugs were generated. Its existing ID/legacy-slug redirect logic could not run for other route parameters. | Permit on-demand job routes, keeping `findJob`, permanent canonical redirects, and `notFound()` for unknown identifiers.                                                | Production checks should request a current ID, its legacy slug, canonical slug, and an unknown slug. Expected results: redirect, redirect, readable detail, 404.                 |
| Medium   | Every snapshot job was prerendered at build time: 2,885 records in this checkout at audit time.                                                                           | Prerender 24 recent details; generate remaining canonical routes and aliases on demand with the existing one-hour revalidation interval.                                | Build should report a bounded generated set. The first uncached request to an older job can take longer than a previously prerendered response.                                  |
| Medium   | Detail pages offered no contextual next role; visitors were sent back to a generic directory when a listing did not fit.                                                  | Show up to three active jobs sharing known skills or role terms. Exclude the current job, archived jobs, and duplicate company/title pairs; show a clear all-jobs link. | Two regression tests cover exclusions, relevance ordering, recency ties, cap, empty results, and input immutability.                                                             |
| Medium   | Eight category routes existed but the common category navigation linked to only six.                                                                                      | Link all eight supported categories.                                                                                                                                    | Inspect `CategoryLinks`; all category slugs are generated from the shared category list.                                                                                         |
| Medium   | Category pages had a short introduction and listings but little guidance specific to each specialty.                                                                      | Add visible, expandable guidance for assessing each role and preparing relevant application examples, plus location eligibility guidance.                               | Content is server rendered, keyboard-operable native `details`, and tailored to each of the eight categories. No fabricated statistics, testimonials, or FAQ rich-result claims. |
| Low      | Category routes had visible breadcrumbs but no breadcrumb structured data.                                                                                                | Add matching `BreadcrumbList` alongside the existing collection schema.                                                                                                 | JSON-LD uses the established escaping helper and canonical URLs.                                                                                                                 |

Existing safeguards preserved: no speculative `JobPosting` for unknown geography, updated-only dates, archived records, or restricted sources; no invented salaries or deadlines; private and empty pages remain noindex; the public API and RSS source redistribution restrictions remain intact.

Targeted ESLint and the two new related-job regression tests passed. Requests to the local development server for the canonical route, ID alias, legacy alias, and unknown slug were blocked by `connect EPERM 127.0.0.1:3000`; no HTTP response was observed. Full build and production route checks belong to the parent audit run.

References: [Google link guidance](https://developers.google.com/search/docs/crawling-indexing/links-crawlable), [Google JobPosting guidance](https://developers.google.com/search/docs/appearance/structured-data/job-posting). These support crawlable descriptive links and accurate job markup; neither guarantees rankings.
